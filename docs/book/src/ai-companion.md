# AI Watch Companion & Hailo NPU

MBL delivers next-generation multimodal media intelligence using on-device neural processing units (NPU) and local LLMs.

## Hailo-8 & Hailo-10H NPU Architecture

On systems equipped with Hailo hardware acceleration (e.g. Raspberry Pi 5 with Hailo AI M.2 HAT):
- **Cooperative Scheduler (`mbl-hailo`):** Manages shared access to `/dev/hailo0` alongside other tenants (such as Frigate NVR) using fair-share time-slicing.
- **Multimodal Video Scene Search:** Generates CLIP visual embeddings for keyframes. Users can search naturally for scenes (e.g., "car chase in the rain", "diner conversation at dusk") with sub-10ms query execution.

## Real-Time AI Watch Companion

The AI Watch Companion protocol (`/api/v1/companion/sessions/{id}/*`) provides real-time co-watching experiences:
- **Live Dialogue Cues:** Extracts WebVTT subtitles and buffers current scene context into a live MCP resource (`mbl://sessions/{id}/live-context`).
- **Scene Explanations & Trivia:** AI models can answer context-aware questions ("Who is the actor that just walked in?") without spoiling future plot twists.
- **Reactions in the player:** a companion joins a session (`POST …/join`) and posts reactions (`POST …/reaction`). The web player polls `GET …/reactions` and shows each reaction on screen for about 12 seconds. The server keeps the latest 50 feed entries per session in memory; they are gone after a restart.
- **Dialogue in the live context:** `GET …/context` (MCP `explain_scene`) includes the chapter, the subtitle line on screen and up to six lines from the last 90 seconds. Lines after the current position are never included. The text comes from the subtitle track the player shows; with subtitles off it comes from the default text track. Image subtitles (PGS, VobSub, DVB) cannot be read. The first request starts extraction in the background and returns `dialogueStatus: "preparing"`. For an embedded track this reads through the whole file once, which can take a while for large files. Afterwards the converted file is cached.
- **Chat and comment mode:** the player always shows a **Chat** button, also before a companion has joined (your messages then wait for one). In the chat you can write to the companions (`POST …/messages`, at most 500 characters) and choose **Comments on**, **Replies only** or **Comments off** (`PUT …/mode`). The choice is remembered in the browser and applied to the next session. With **Replies only** the server only accepts companion posts that answer one of your messages (`replyTo`). With **Comments off** it refuses all companion posts. The chat scrolls to the newest message. Only the person watching can write in the chat or change these settings.
- **How often and Comment now:** with **Comments on** you choose **Low** (about every 10 minutes), **Medium** (about every 4 minutes) or **High** (about every 90 seconds) for unprompted comments (`frequency` in `PUT …/mode`). **Comment now** (`POST …/nudge`) asks the companions for a comment at once; in **Replies only** mode it allows one comment that does not answer a message. A green dot on the Chat button means a companion is listening and will answer within seconds.
- **Built-in companion:** when an admin has turned on the AI assistant (Server settings → AI assistant: a provider such as Claude, OpenAI, Gemini or a local Ollama), the server itself answers in the chat as **MBL**. It joins a session the first time you write or press **Comment now**, answers with the scene so far as context, uses only read access to your own libraries, and never comments past your position. Unprompted comments then follow your chosen frequency. It stays quiet with **Comments off** and steps aside while an external agent is listening.
- **Screenshots to the AI:** off by default, because the picture leaves the server for the AI provider. In the player chat, choose **Every 30 seconds**, **Every minute** or **Every 5 minutes** (`frames` in `PUT …/mode`). The server then takes a picture of the scene at your position (never from later, at most 768 pixels wide) and reuses it for that interval. The built-in companion sends it with your question, and the assistant chat can look at your screen when you ask what is on it. A model that cannot take images gets the question without the picture. Agents fetch it with the MCP tool `get_companion_frame` (without `session_id` it uses your own current playback) or `GET …/frame`. One picture is taken at a time, so a busy server skips rather than piles up work.
- **What the assistant may do:** under **What the assistant may do** an admin chooses, for administrators and for other users, which kinds of tools the chat gets: playback, libraries and collections, Live TV, and for administrators also users, remote access or everything. Reading is always on; other users can never get admin, user or remote tools, and the assistant never gets more than the person asking. It is told to describe and wait for a yes before changing anything, and to use `dry_run` where a tool has it. With playback allowed it can start a title in your browser (`play_here`) or on another device. The player's companion always only reads.
- **Agent program as the assistant:** instead of a language model the admin can choose **Claude Code** or **Other agent program** and enter a command line (no shell; `{mcp_config}` is replaced with a file path). For each answer MBL creates a temporary read-only API token for the person asking, writes an MCP configuration with it, runs the command with the question on standard input and shows what it prints. `MBL_MCP_URL`, `MBL_MCP_TOKEN` and `MBL_MCP_CONFIG` are set; the token is revoked and the file removed afterwards. The suggested Claude Code command is `claude -p --mcp-config {mcp_config} --strict-mcp-config --allowedTools mcp__mbl --output-format text`; Claude Code must be installed and signed in for the server's user. The program can use any read tool of the person's MCP view (not only the built-in allowlist), and an answer may take up to three minutes.
- **For agents:** join with `join_watch_session`, then call `wait_for_companion_events` (REST: `GET …/wait?botName=…&afterId=…`) in a loop. It returns as soon as you write, press Comment now or a scheduled comment is due (`commentDue`: `requested` or `scheduled`), and otherwise after at most 25 seconds (`timedOut`). Each answer includes the live context (position, chapter, dialogue so far) and `lastId` to pass as `after_id` next time. `read_companion_chat` reads the whole feed.
- **Scene search in the web app:** **Scene search** (`/discover`) finds indexed scenes from a description and starts playback at the scene. Administrators index a library with **Index scenes** (a background job that pauses during playback and skips titles that already have scenes) and can run **Test AI speed**. Without a Hailo NPU the CPU fallback is used, which is slower and less precise.
- **Spoiler-Free Recaps:** **Previously on…** on a show or season page. Generates "Previously on..." episode summaries constrained strictly by the user's recorded watch history.
- **Subtitle Auto-Sync (`mbl-subsync`):** Employs Voice Activity Detection (VAD) and energy envelope correlation to align out-of-sync external subtitle tracks within ±100 ms precision.
